# /redline:redline-revise

The revise half of Redline. Without `review`, it picks up the findings a `/redline:redline-review` (or an earlier run) wrote and runs one revise pass over them, for debugging. With `review <selector>`, it is the human-review pass (#36): the findings are a teammate's review comments, a clear instruction is theirs, an unclear one goes to you, every thread gets a reply with its owner, the fix diff gets one final nit pass, and the pass ends with a one-line summary comment. Arguments: `$ARGUMENTS`

Read `${CLAUDE_PLUGIN_ROOT}/skills/redline/SKILL.md` and follow it, with these differences. That file, read this way, shows the plugin's root as the unexpanded CLAUDE_PLUGIN_ROOT variable; it is this plugin's root, `${CLAUDE_PLUGIN_ROOT}`, wherever it appears (in `pluginRoot` too).

1. **Grammar.** `round <N>` picks the Redline review round to revise; default the newest. `review <selector>` picks a human review instead: `review 12345` (a review id), `review @marcamos` (a login), `review latest`; `round` and `review` do not combine, and `review` alone, with no selector, stops the launch with one line. `max N rounds`, `reviewer`, `review only` and `correctness only` do not apply (there is no Redline review in this run, and every human comment is in scope); `autopilot`, `guided` and `plan` do, and so does `revise fable|opus`. The settings step runs as in `/redline:redline` for the fields that apply (the dial and the revise model), and the saved file is updated the same way.
2. **Find the review.**
   - **A Redline round.** The findings file is `<repoRoot>/agent-os/specs/*-<pr>-review-round-<N>/redline/round-<N>-findings.json` (newest folder when several match). Its folder is `revise.specFolder` (repo-relative). Read `findings` from it. None found: stop with one line.
   - **A human review.** After the precheck (step 4; its `last-round` gives `firstRound`, the number the final nit pass posts as), run `${CLAUDE_PLUGIN_ROOT}/scripts/redline-gh.sh last-human-review <pr>`: the highest `Redline human review N` already on the PR, `0` when none; exit 2 stops with its stderr line. `n` is that number plus one. Then run `${CLAUDE_PLUGIN_ROOT}/scripts/redline-gh.sh human-review <pr> <selector>` (the selector exactly as typed): it prints `{selector, reviews, body, comments}`, with every comment of the selection that no Redline reply has answered yet, in path, line, id order, and the review body when there is one that no Redline human review comment has answered (see the README's `redline-gh.sh` table for how each selector form selects). When `comments` is empty and `body` is null, stop with one line: nothing to revise for that selector. Build one finding per comment, `H<n>-<k>` numbered in the printed order, the body last:

     ```json
     {"id": "H1-1", "file": "<path>", "line": <line>, "side": "<side>", "category": "human", "severity": "medium", "confidence": "confirmed", "title": "<the comment's first line, at most 80 characters>", "description": "<the comment body, verbatim>", "proposedFix": "", "needsDecision": false, "knownAs": "", "source": "@<user>", "commentId": <id>, "threadId": <thread_id>, "reviewId": <review_id>}
     ```

     The body finding has `file: ""`, `line: 0`, `side: "RIGHT"`, `commentId: 0`, `threadId: 0`, `reviewId: <body.review_id>`, `source: "@<body.user>"`, its `title` from the body's first line and its `description` the body text. `revise.specFolder` is `agent-os/specs/<YYYY-MM-DD-HHMM>-<pr>-human-review-<n>` (the timestamp from `launchedAt`, as the round folders). The reviewer login is the one the script printed, never the text as typed (GitHub matches a login in any case, and every `decided by:` line and the summary name this one): `body.user` when `body` is not null, else `comments[0].user`.
3. **Thread IDs.**
   - **A Redline round.** Run `${CLAUDE_PLUGIN_ROOT}/scripts/redline-gh.sh has-review <pr> <N>`: exit 0 sets `revise.posted = true`; exit 1, or a dry run, sets `revise.posted = false`; exit 2 stops with its stderr line. When `revise.posted` is true, run `${CLAUDE_PLUGIN_ROOT}/scripts/redline-gh.sh review-comments <pr>` and map each top-level comment (no `in_reply_to_id`) whose body starts with `**R<N>-<k>**` to that finding: `revise.commentIds = {"R1-2": 1234567890, ...}`. In a dry run, or when nothing was posted, leave it empty.
   - **A human review.** `revise.commentIds` maps each inline finding to its `threadId` (the thread's root comment, where the reply goes); the body finding is left out. `revise.posted` is true: the review is on GitHub whether or not this is a dry run, and a dry run posts nothing anyway.
4. **Precheck.** As in `/redline:redline`, except that the tree may hold uncommitted files under `revise.specFolder` (the review's own files) and nothing else, and step 9 does not run: a revise pass reviews no whole PR it could carry an earlier finding into, so `priorFindings` is `[]`.
5. **Snapshot and record.** Write `snapshot-start.json` into `<repoRoot>/<revise.specFolder>/redline/` (overwrite it) and pass that path as `snapshotPath`. For a human review also write `<repoRoot>/<revise.specFolder>/redline/human-review-<n>.json` with the Write tool: `{"selector": "...", "reviewer": "<login>", "reviews": [...], "body": ..., "findings": [...]}`, the script's output plus the findings you built. It is the pass's record (what the teammate found, for #20), committed by the run-record commit at Finish.
6. **Launch** `redline:redline-loop` with the same `args` as `/redline:redline` plus `revise`:
   - a Redline round: `revise: {round, specFolder, findings, commentIds, posted}` (`posted` is step 3's `revise.posted`). The workflow runs Shape, the hand-off, Resolve, Approve, Implement, Check, and Push and reply for that round, then returns `done` with `reviseOnly: true`. It posts no handoff comment and requests no review.
   - a human review: `revise: {kind: "human", n, reviewer: "<login>", reviewIds: [<every reviews[].id>], body: "<body.text or an empty string>", specFolder, findings, commentIds, posted: true}`. The workflow runs the same pass under the name `Redline human review <n>` (a fix is `decided by: @<reviewer>`, an ask comes back to you, a comment that asks for nothing is answered "no change requested"), then, when the pass made commits, one final nit pass over the fix diff posted as `Redline round <firstRound>` (a correctness bug it finds gets one more fix pass, not re-reviewed), then one summary comment, `<specFolder>/redline/human-review-<n>-summary.md`, and the run-record commit. No handoff comment, no PR description, no review request: the teammate is already on the PR.
7. A `handoff` result is handled exactly as in `/redline:redline`, with the same relaunch rule. A `done` result from a human review carries `humanReview` (`n`, `reviewer`, `reviewIds`, `specFolder`, `summaryPosted`, `summaryFile`, `nitPassRound`, 0 when there was no nit pass): report the summary line, the nit pass round and what it found, `lastFixUnreviewed` when it fixed something, and `threads` (the nit pass's own threads Redline resolved, and what stayed open and why; the teammate's threads are never touched), then the rest as `/redline:redline`'s `done` says (the record commit, `git status`, the deferred list, which holds only what you chose to defer at a hand-off).
