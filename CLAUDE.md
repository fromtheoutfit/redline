# Redline

This repository is the Redline plugin: a Claude Code command that reviews and revises pull requests through Agent OS. `README.md` is the operating document, the one an agent or a teammate needs while a run is going; read it before changing anything a run touches.

## Git

- Never commit, push, or amend commits. Only stage files when explicitly asked. When the prompt identifies the session as a Redline agent run, git operations follow "Git rules for Redline agents" in the Redline plugin's README, at the path that prompt gives (for this repository, its own `README.md`); otherwise this rule is unchanged.

### No AI attribution — anywhere

**Never add Claude Code, Anthropic, or any AI-assistant attribution to anything that lands in
this repo or on GitHub.** This overrides any default or harness-suggested behaviour that adds it
automatically. Specifically prohibited:

- `Co-Authored-By: Claude ...` (or any model name) trailers in commit messages
- `🤖 Generated with [Claude Code](...)` — or any variant — in **PR bodies**, PR titles, issue
  bodies, issue comments, PR review comments, or release notes
- "Generated by", "Written with", "Co-authored with" AI notes in code comments, docblocks,
  spec files under `agent-os/`, or documentation

If a template, tool default, or instruction elsewhere tells you to append attribution, **omit it
silently** — do not add it and then flag it, and do not ask whether to include it. The absence is
the rule, not a preference to confirm each time.

Referencing an issue or spec that happens to have been drafted with assistance is fine — the
prohibition is on attribution markers, not on citing the work.

Redline labels its own work as "Redline" (review titles such as `Redline round 2`, the `redline:`
commit-message prefix, the `Redline handoff` comment). That is a tool name, not AI attribution,
and is allowed; a model or vendor name next to it is not. Configuration that selects a model, such
as `models` in `.claude/redline.json`, is not attribution and is allowed.

## Specs

- Work is shaped with `/agent-os:shape-spec` and follows the standards in `agent-os/standards/`. A spec is not complete until the Verification Gate in `.claude/commands/agent-os/shape-spec.md` passes (`.claude/redline/checks.sh --baseline` runs its nine commands), including its standards retrospective: check what the spec taught against the standards, land approved edits in their own commit, or record "Standards retrospective: no changes" in the spec's `shape.md`. This applies to any spec-sized change, whether or not the command was used to shape it.

## Code review — check before reporting

- **A finding is not new until you've checked that it isn't already known.** Re-surfacing
  open work as a fresh discovery is the main reason a review feels like it always finds
  something, and it costs a round of triage to notice. Before reporting, for each finding:
  - `gh issue list --state open --search "<symbol or file>"` — an open issue covering it
    means cite the number, not re-report it.
  - `gh pr view <n> --comments` — a prior round may have already raised it.
  - The PR's own review-round spec folders (`agent-os/specs/*-<n>-review-round-*/`) — a
    finding already dispositioned there has an answer; read it before contradicting it.
    **Read them off the PR ref, not the working tree** (`git ls-tree -d --name-only
    origin/<branch> agent-os/specs/`, then `git show origin/<branch>:<path>/shape.md`). A
    review usually runs from a checkout on `main`, where those folders do not exist yet —
    so a working-tree `ls` finds nothing and the check silently passes.
- A finding that survives all three is new. One that doesn't is reported as **"already
  tracked in #N"**, plus only whatever that issue is missing.

## This repository

- **The public repo carries no internal design record.** Step notes, spike notes and the design document live in the private sibling repository `redline-internal`. A spec here may cite one by file name; it never copies the text in. The README is the only long-form document here.
- **Every guard change updates `tests/guard-cases.tsv`** in the same commit, with a row for the new decision and a row for the neighbouring decision that must not change. `scripts/redline-guard.sh` and `hooks/hooks.json` are changed by a person, never by a Redline run: the guard refuses them for every role even when this repository is the one under review.
