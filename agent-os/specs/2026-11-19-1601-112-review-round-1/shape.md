## Decisions

1. **R1-4 (correctness, low, fix).** Unattended answer 8. The pinned `git diff` (365-367) passes `-U3`, and git's manual says `GIT_DIFF_OPTS` overrides it. With `-u0` exported, a comment on a context line of a patch-less file on the clone path is moved under the off-hunk line though GitHub would take it; with a larger value a comment past GitHub's three lines of context is placed, refused, and the fallback moves every sourced comment. Task 2 runs that one call as `env -u GIT_DIFF_OPTS git ...` (BSD and GNU `env` both take `-u`, scripts/bash-conventions, line 40), says so in the function's comment, and adds a case beside the pinned-configuration one that exports `GIT_DIFF_OPTS=-u0` and expects the same placement.
   Decided by: redline
2. **R1-5 (correctness, low, decline; second look: unconfirmed).** The second look tried what the verifier said would confirm it: the files listing of a pull request whose only change to a text file is `chmod +x`, and of one that removes an empty file. Neither can be read here: the shaper's read subcommands are `issues-search`, `pr`, `pr-comments` and `review-comments`, not `files`, and no pull request of this repository has either case to read (`git log --summary --format= origin/main` shows no `mode change` line; `git log --raw --no-abbrev --format= origin/main` shows no change to or from the empty blob `e69de29`).
