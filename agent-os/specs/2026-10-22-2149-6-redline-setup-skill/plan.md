# Spec: `/redline:setup` (issue #6, second half)

Spec folder: `agent-os/specs/2026-10-22-2149-6-redline-setup-skill/`

## Context

Two repositories (Chalkboard, Losers League) were set up for Redline by hand, and the README's eight-step checklist is the only guide. Both ports hit the same traps: a baseline lost to a stale `vendor/` or `public/build`, a gate that disagrees with CI, a `settings.json` merged by eye. Issue #6 asks for `/redline:setup`, an interactive skill run from the repository root that reads what it can off the repository, asks about the rest, and writes the contract. The first half of #6, the gate stamp, shipped in #7 and #8: `scripts/redline-gate.sh extract|stamp|check`, the precheck's stamp check, and the `# redline-gate:` placeholder in `scripts/checks-template.sh`. This spec ships the skill, which uses them and does not rebuild them.

Outcome: a third repository gets the contract from one command; a rerun on a set-up repository changes nothing when nothing drifted and shows each diff otherwise; this repository's own contract is reproducible from a clean clone; the scriptable parts are covered by the gate.

## Decisions (from the brief and the shaping questions)

- Skill at `skills/setup/SKILL.md`, frontmatter `name: setup`, typed `/redline:setup`; follows the issue's 13 steps. Step 13 hands back: file list, baseline result and time, a suggested commit message and PR title. **The skill never commits.**
- Step 3's command/prose split is a conversation with the person; the stamp hashes all backticked content regardless (#7).
- Step 5 calls `redline-gate.sh stamp`; a rerun on a stamped repo calls `check` first and diffs the command list only when the stamp mismatches.
- Step 4 (environment vs lockfiles) includes built assets; with browser tests, build before the baseline.
- Rerun on a repo with the contract: changes nothing when nothing drifted; otherwise shows each diff and asks.
- #11 scope here: setup writes `# redline-template: checks-template.sh v1` as the header line immediately above the stamp (the stamp stays the header's last line, which `redline-gate.sh` relies on). The precheck gains one line that warns, never stops, when the repo's version is older than the template's or missing. The template-function port on rerun stays with #11.
- `checks.sh` is **generated** by `redline-setup.sh checks` from a committed JSON description, **`.claude/redline/checks.json`, the source of truth**: `checks.sh` is never hand-edited; a change is an edit to `checks.json` followed by a regenerate (the README, the template's header and the unattended section's point 11 say so). This repo's own `checks.json` and regenerated `checks.sh` are committed (dogfood), so a fresh run on a clean clone reproduces both, and a rerun's regenerate is a no-op. The input is kept minimal (names, commands, recorded flags, the baseline) so a person's answers are few; the header prose is the generator's. The guard already refuses `.claude/redline/` to every role, so no role can write `checks.json` either (pinned by a guard-cases row). For a repository whose `checks.sh` was hand-written (Chalkboard, Losers League), the first rerun bootstraps `checks.json` from `read-checks`, shows it, regenerates, and the diff against the hand-written file is the person's to accept.
- One new script, `scripts/redline-setup.sh` (subcommands below), the skill's only, no guard group, pinned by guard-cases rows, not in the allow-list template (setup is interactive; the permission prompt doubles as the person's confirmation). One new harness, `tests/setup-test.sh` over `tests/setup-fixtures/`, which becomes gate step 7 (restamp in the same commit).
- Clean-clone evidence: both a rerun (nothing drifted, `git status --porcelain` empty) and a fresh run on a stripped clone (diff against the committed contract empty; known deviations recorded, see Task 10).
- Standards: all eight apply. Product: roadmap item 7 and tech-stack counts updated.
- References: `scripts/redline-prefs.sh`, `scripts/redline-gate.sh`, `tests/prefs-test.sh`, `tests/gate-test.sh`, `skills/redline/SKILL.md`, the Chalkboard and Losers League contracts (`~/Code/Sites/chalkboard`, `~/Code/Sites/loser`: `.claude/redline/checks.sh`, `.claude/settings.json`, `.claude/redline.json`, the unattended section, CLAUDE.md, `.gitignore`), `redline-internal/docs/STEP14-NOTES.md` (cited by name only). No visuals.

## The script: `scripts/redline-setup.sh`

Style of `redline-prefs.sh` / `redline-gate.sh`: `set -euo pipefail`, header in the standard order (what, usage, environment, output, exit codes), jq for every JSON value, `python3 -I -c "$PY"` fed on stdin for text surgery, a temp file beside the target then `cat > target` (keeps the mode bit), one JSON object on stdout, usage errors exit 2. Every writing subcommand takes `--dry-run` (same JSON, `written: false`) so the skill can show a diff before asking. "No change" is `{"changed": false, "written": false, ...}`.

| Usage | Prints | Exit |
| --- | --- | --- |
| `settings <repoRoot> [--allow <entry>]... [--dry-run]` | `{file, existed, changed, written, added: [...], keysAdded: [...]}` | 0; 2 bad args, existing file not JSON or carries a BOM |
| `gitignore <repoRoot> [--dry-run]` | `{file, existed, changed, written, line, after: "<line placed after>" \| null, at: <line no>}` | 0; 2 |
| `unattended <shape-spec.md> --gate-steps <m>-<n> --prose-steps "<text>" --retro-step <n> (--pr-body-standard <name> \| --no-pr-body) [--force] [--dry-run]` | `{file, present, changed, written, fillins, found \| null, differs: {field: {have, want}}, insertedAt}` | 0 inserted or up to date; 1 present with differing fill-ins and no `--force`; 2 bad args, no `## Prerequisites`, no following `##` |
| `config --reviewer <handle> --baseline-seconds <n> [<repoRoot>] [--force] [--dry-run]` | `{config: {...redline.json...}, file, existed, changed, written, differs}` | 0; 1 exists and differs without `--force`; 2 bad args |
| `checks <checks.json> <checks.sh>` | `{file, written, changed, stampKept, checks: [names], templateVersion}` | 0; 1 a template anchor is missing; 2 bad input (reasons on stderr) |
| `read-checks <checks.sh>` | `{file, templateVersion \| null, stamp \| null, checks: [{line, step, name, recorded, cmd \| null, source \| null, guard: null \| "REDLINE_OCTANE" \| "base_ref"}], input: {...}}` where `input` is a best-effort `checks.json` for the bootstrap (steps, formatter, octane, `vars`, `alwaysAllowed` recovered; `repo` and `baseline` null, to be filled) | 0; 2 unreadable |
| `version <checks.sh>` | `{template: "v1", file: "v1" \| null, match}` | 0 match; 1 mismatch or missing line; 2 unreadable |

Rules per subcommand:

- **settings**: `existing * template` (recursive merge, existing key order kept, template keys appended), then `permissions.allow` = existing entries in order + template entries not present + `--allow` extras not present (exact string match, no `unique`, which sorts). Changed = `jq -S` of before and after differ (semantic), so a file `claude plugin install --scope project` reordered reads as unchanged and keeps its bytes. Missing file: created from the template plus extras (`mkdir -p .claude`). Never reads or writes `settings.local.json`.
- **gitignore**: the line `.claude/redline.local.json` (or `/.claude/...`) present means no change. Else after `.claude/settings.local.json`, else after the last `.claude/` or `/.claude/` line, else appended (adding the missing final newline first). Missing file: created. Keeps CRLF when the file uses it.
- **unattended**: present = a heading `^#{2,} Unattended mode \(Redline\)`. The four fill-ins are read back from the section (`\(gate steps (\d+) to (\d+)`, `Gate step (\d+)'s edits`, the "Steps ... stay(s) as written" phrase, point 11's ``(per `<name>`)`` or absence). Equal: up to date. Different: exit 1 with `differs`, file untouched; `--force` patches those phrases in place inside the section only and appends or removes point 11 as a whole line, never re-pasting the body, so hand edits survive (this repo's point 11, Loser's point 2). Fresh insert: the template text after its first `---`, fill-ins applied, placed before the first `##` after `## Prerequisites` outside any fence (Prerequisites holds a fenced block; reuse the gate parser's fence pass), one blank line each side; BOM and CRLF preserved. The inserted section adds no "verification gate" heading, so the gate hash never moves (tested).
- **config**: three substitutions into `templates/redline.json.example` (`reviewer`, `checker`, `checkerStallMs`), validated with `jq -e`, so a fresh write is byte-identical to the three repositories' hand-written files. `checker` = `git-only` when seconds > 300 else `full`; `checkerStallMs` = max(300000, ceil(seconds × 1.7 / 300 s) × 300000) (29 → 300000; 299, 300, 301 → 600000; 1048 → 1800000, Loser's committed value). `@` stripped from the handle. Existing file: `jq -S` compare; differing → exit 1 with `differs` per top-level key (a hand-changed `maxRounds` is the person's), `--force` overwrites.
- **checks**: deterministic; the input file is the repository's committed `.claude/redline/checks.json`. Input: `repo` (phrase after "Redline gate for"), `gateFile`, `selfHosted` (default false; drops `<plugin>/` from the stamp advice and names `README.md`), `alwaysAllowed` (array; default empty), `vars` (`[{name, env, default, doc}]` → an Environment header line and `name="${ENV:-default}"` after the `trap` line), `formatter` (`{step, name, cmd}` → the template's `tree_state` before/after block, recorded 1; `null` → one comment line), `octane` (`{step, cmd}` → the `REDLINE_OCTANE` block; `null` → the Environment line says it is ignored), `baseline` (`{seconds, date, note?}`, or `null` before the baseline has run: the header then says "Baseline: not recorded yet", and step 6 fills it in and regenerates), `steps` (`[{step, name, recorded, cmd | source, title?, kind?}]`, emitted in gate order; `name` unique `[a-z][a-z0-9-]*`; `cmd` is the runtime string, escaped for double quotes so `bash -c` receives the JSON string and `read-checks` returns it; `source` is emitted verbatim for a step that expands a shell variable (`$migrate_db`); `kind: "base-diff"` with `source` emits Chalkboard's `if env_base="$(base_ref)"` block; a `cmd` with a newline is refused). Header, in the template's order, paragraphs separated by a bare `#` and never an empty line (`sed -n '2,/^$/p'`): what the script is (repo, gate file, step range); usage (verbatim); environment (`REDLINE_OCTANE`, then `vars`); the checks list, one line per step `<name>  <cmd>  (gate step n: <title>)` with the formatter marked recorded; the baseline line (`Baseline on <date>: <n> seconds<, note>, so checker: <mode> is the right mode`); snapshot and allowed; exit codes; the stamp explanation (verbatim); one line saying the file is generated from `.claude/redline/checks.json` and is not hand-edited; `# redline-template: checks-template.sh v1` (copied from the template's own line, never hard-coded); then the stamp line: the existing file's `# redline-gate:` line when there is one (`stampKept: true`, so a regenerate never loses a stamp and a no-op rerun is byte-identical), else `# redline-gate: TODO ...`, as the last header line. Body: spliced from `scripts/checks-template.sh` by anchor lines (`set -euo pipefail`, the `ALWAYS_ALLOWED` comment and assignment, the `trap` line, the `todo()` helper, `if [[ "$mode" != "git-only" ]]; then` and its closing `fi`); a missing anchor exits 1 naming it, so the template and the generator cannot drift silently. Output `chmod +x`. `changed` compares bytes with the existing file and nothing is written when it is false. `REDLINE_TEMPLATE=<file>` overrides the template for tests.
- **read-checks**: parses `run_check <name> <0|1> "..."` lines, the gate step from the comment above each, the enclosing guard, the `name="${ENV:-default}"` lines, `ALWAYS_ALLOWED`, and the two header lines; `input` is the recovered `checks.json`. Used only to bootstrap `checks.json` on a repository whose `checks.sh` was hand-written; a `source` step is recovered verbatim.
- **version**: `grep -m1 '^# redline-template:'` on both files.
