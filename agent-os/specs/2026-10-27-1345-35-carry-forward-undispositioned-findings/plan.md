# Carry forward undispositioned findings (#35)

Spec folder: `agent-os/specs/2026-10-27-1345-35-carry-forward-undispositioned-findings/`

## Context

Losers League #778: a review-only run posted round 1 (R1-1 to R1-3), a later run errored at `post` before shaping, the person committed the round-1 folder, and a fresh run started at round 2. Round 2 re-reviewed the whole PR, found R1-2 again, and dropped it as "already reported": the reviewer's known-finding check matched it against round 1's record. The run ended "no deferred items" with a known correctness bug untouched.

The check equates *recorded* with *dispositioned*. They differ whenever a round posts its review and then stops: review-only, an error after `post`, a cap hit, a hand-off never relaunched. Today the reviewer does the check alone, in free text, from `review-comments`, `pr-comments` and the working-tree spec folders (`agents/redline-reviewer.md:14-22`, `workflows/redline-loop.js:774-780`), and the loop drops any finding with a non-empty `knownAs` (`loop:2268`). A fresh run at round N>1 gets nothing about earlier rounds but the number (`args.firstRound`, `loop:77`).

Shaped by hand on 2026-10-27 with `/agent-os:shape-spec`; the person makes the commits.

## Decisions (the issue's seven, plus the ones made while shaping)

1. **Tracked vs. carried, by the reply.** The evidence that an earlier finding was dispositioned is the Redline reply answering it: the `Redline round N:` reply in its thread, or the issue comment behind its marker for a body finding. `shape.md` is not consulted (a hand-off folder never relaunched already reads `Decided by: redline` on fixes never made; a dropped finding exists only as a reply). The reply's fixed wording (`replyBody`, `loop:718-736`) gives the label: `fixed in` → `fixed`, `mitigated` → `deferred`, `not acted on in this run.` → `dropped`, `not changed in this round.` → `not-changed`, `carried forward as R<n>-<k>;` → `carried`, anything else → `decided`. No reply → `none`. **Tracked:** fixed, deferred, decided, dropped, carried. **Carried forward:** none, not-changed (decided 2026-10-27: a fix that never landed is not handled).
2. **A finding carried once is tracked afterwards.** A review body's finding line ending `· first reported as R1-2` marks R1-2 as `carried` (to that id) as soon as the round is posted, whatever its threads say, so a third run never carries both R1-2 and R2-1. R2-1 carries its own disposition.
3. **The list enters through `args.priorFindings`**, read by the skill's precheck with a new read subcommand `redline-gh.sh prior-findings <n>` (as `firstRound` does, `replay.md`): the workflow script cannot read files or GitHub, and the run itself changes the old threads once it replies in them. `[]` when `firstRound` is 1. A relaunch reuses it byte for byte.
4. **The reviewer matches against structured lists, not prose.** The first round's prompt carries two JSON lists: already tracked (match → `knownAs: "R1-1: fixed"`) and carry forward (re-verify at the current head: still holds → a finding of this round with `carriedFrom`; no longer holds → `resolved: [{id, why}]`). Every carry-forward id appears in exactly one of the two. Issues, teammate comments and human-review folders stay the reviewer's own check, as today.
5. **The loop enforces the accounting.** A carry-forward id the reviewer neither carried nor resolved is carried by the loop as reported (old title, file, line, body; a warning names it) rather than dropped: the shaper investigates it, and `place` moves it into the body if the line no longer anchors. A `carriedFrom` naming a tracked or unknown id is cleared with a warning; a `resolved` entry naming one is ignored with a warning.
6. **The note is composed by the loop.** The inline comment of a carried finding gets the line `First reported as R1-2 in Redline round 1.` after its title; the finding line in the review body ends `· first reported as R1-2`. The reviewer writes a fresh description and never copies the old text.
7. **Review body headings.** `### Findings (n correctness, m nit)` holds the fresh findings; `### Carried forward from earlier rounds (n correctness, m nit)` the carried ones; `### Resolved from earlier rounds` one line per resolved id (`- **R1-4** title: why`); then `### Already tracked` as today. `No findings.` only when nothing is active.
8. **Old threads get a reply and are swept** (decided 2026-10-27). When a carried finding is settled, dropped or not changed, its earlier thread gets one reply from this round, `Redline round 2: carried forward as R2-1; <the tail of R2-1's reply>` (so `fixed in abc1234 (...) · decided by: redline`, or `not acted on in this run. <reason> · decided by: @login`). A resolved earlier finding's thread gets `Redline round 2: resolved; first reported as R1-4 in Redline round 1. <why> · decided by: redline`. A body finding's reply is an issue comment behind its old marker with the old round's header. Finish's sweep names the old root, any earlier Redline reply in it, and this round's reply, so the script's every-comment rule holds and a teammate's comment keeps the thread open. The duplicate check for a reply becomes "a reply in that thread opening with this pass's title": an earlier round's `not changed` reply is not a duplicate.
9. **Handoff section `### Earlier rounds`**, one line per prior finding: `carried forward as R2-1: <outcome>`, `carried forward as R2-3, out of scope (correctness only)` when the scope filter dropped a carried nit, `resolved: <why> · decided by: redline`, or `already handled in round 1: <reply text>`.
10. **Only the run's first round carries** (the whole-PR review). Re-reviews, final nit passes, `redline-revise round N` and human review passes are unchanged; `carriedFrom` defaults to `""` there.
11. **Review dial, review only, dry run** need no special path: carried findings are findings. A `review only` run at round N>1 posts them under their heading. A dropped carried finding is tracked next time (its reply says dropped) and its old thread gets the carried-forward reply with the drop.
12. **Guard:** `prior-findings` joins `GH_READ` and the header line (bash-conventions), with guard-cases rows; only the skill runs it. The person makes that commit.
13. **Accepted:** a teammate's comment in an old thread is answered, for `human-review`'s rule, by the carried-forward reply after it, as by any Redline round reply; the sweep still skips that thread. Recorded in `shape.md`, not a Known limit.
