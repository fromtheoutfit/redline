# PR #127 by hand: every new key states its place

## Context

The self-review of pull request #127 (run `wf_6478a046-32b`) stopped twice at `shape r2` on the same check. A real shaper called two fixes sweeps and returned `swept` on the finding, beside `cause`; the schema and `checkCauses` read `cause.swept`. Nothing the shaper reads says where the list sits: not the template, its own agent file, the prompt's ask or the stop's message, and no example shows a sweep.

This is the by-hand fix on the branch before a fresh Redline run. It fixes that instance everywhere it is stated, and settles the class: every key #127 added that sits inside another object or beside one. R2-2 is fixed here because it changes the same return example. R2-1 and R2-3 to R2-7 stay with the fresh run.

The returns as recorded, the decisions and their answers, how the tables were built, both tables, the 41 runs and the drafted issues are in `shape.md`. This file is the build.

## Design

**One reading per key.** A key is read in one place. Nothing here makes the workflow accept one in two.

**The instance.** `swept` is stated with its place wherever it is stated: template point 5 and the sentence under point 10's example, the shaper file's rules 3 and 10, `CAUSE_ASK`, and the stop, which names `cause.swept` and says where the list was found when it sits one level out. Both examples gain a fix whose `cause` is a sweep, with the list nested.

**The class, second layer: the workflow's own checks.**

| Found one level out | And its place | What happens |
|---|---|---|
| `where`, `outcome`, `why` or `swept` on the finding; `member` or `found` on `cause`; `cause` beside `findings` | empty | the existing stop of `checkCauses`, whose message now names the key by its full path and says where it was found |
| `ends` on the call; `recommended` on the finding or as a flag in an option; `draft` on a left call, or its fields flat on the option | empty | the existing stop of `checkOptions`, the same way. A relabelled left call with `draft` on the call stops too, where today it is not held |
| any of those | filled | a warning that names the stray copy; it is ignored |
| `draft` on an ordinary call | not read there | dropped with the warning a draft on an ordinary call's option gets |
| `sameClassAs` beside `findings` in a review | - | a warning that names `findings[].sameClassAs`; no link is kept |
| `sameClassAs` on its finding, no list of ids | - | cleared with a warning |
| an entry of `args.decisions` that is no object | - | refused before any agent runs |
| a decision with no `option` whose choice is the label of an option of its call | - | a warning at resolve: read as the person's own words; for a left finding, that it stays left and nothing is filed |

Every fault of a result still goes out in one error (`workflow/replay`; #127, R1-5), and each message keeps its opening words, which the loop test's own-check list matches.

**The class, first layer: the schema, if Task 2 proves it.** The shaper's schemas, for both passes, and the link-asking review's schema refuse unknown keys, so a misplaced key is refused in the agent's own run. The first review of a pull request with no earlier round keeps its schema, so it still replays; the resolve agent's and the GitHub agent's schemas stay open (the GitHub agent returns its file's whole block).

**Template v7.** The body changes, so the marker moves: v6 is frozen under `templates/history/` and pinned as it is, v7 is pinned, and this checkout's section is regenerated by the setup merge. The plugin stays 0.5.0: #127 already bumps it and nothing of it is merged or tagged.
