- **Title:** Decide how a revise-only pass treats a round folder an earlier run already shaped and resolved
- **Found:** `/redline:redline-revise <pr> round <N>` takes the findings file of the newest `*-<pr>-review-round-<N>` folder and makes that folder `revise.specFolder` (`skills/redline-revise/SKILL.md`, step 2), so the pass shapes in a folder an earlier full run may already have shaped and resolved, one that holds the person's decided entries (each ending with a `Decided by:` line) and the tasks written for them. Before any resume, the first shape is told only to complete or correct the folder it finds (rule 9 of `agents/redline-shaper.md`), so nothing protects those entries there either. A round folder a launch creates under its own stamp holds no decision when its first shape is resumed, which is what #117 measured; the revise-only debug path is the one place where a first shape can meet decided entries.
- **Why:** The pull request that found it (#120, review round 1 of #117) only corrects the claim, in the `resumeLine` comment, `docs/running.md` and the replay standard, that no decision can be on disk when a first shape is resumed: the behaviour on this path is the same as before #117, the path is a debug entry point, and the entries survive in the earlier run's record commit, while changing it needs `resumeLine` to learn that a pass is revise-only over an existing folder, new loop-test cases seen red, and changes to rule 9 of the shaper's file, `docs/running.md`, the replay standard and possibly `skills/redline-revise/SKILL.md`, a change of its own rather than a review-round fix.
- **Full fix:** Decide what a revise-only pass over a round an earlier run shaped and resolved does with that run's spec folder, and make the unresumed first shape and its resume agree. Either shape in a new folder under the pass's own launch stamp, so the earlier run's record is never touched and the from-scratch resume stays safe; or have the revise-only branch of `workflows/redline-loop.js` (or the skill, when the folder held `shape.md` at launch) pass a flag that `resumeLine` reads to give that pass's resumed `shape r<N>` a correct-in-place clause like a reshape's (keep the decided entries and their tasks, restore what is missing, never write a lost entry from memory), with rule 9 of `agents/redline-shaper.md` telling the unresumed first shape to keep any decided entry it finds. Either way, add loop-test cases for a revise-only pass over a resolved round that stops at shape and is resumed, seen red first, with a neighbour that pins the first shape of a launch's own folder byte for byte, and update `docs/running.md` ("Run markers and resume") and `agent-os/standards/workflow/replay.md` (line 19) to match.
