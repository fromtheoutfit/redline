# Tell a reshape resumed after any shape-stage stop to correct its spec folder in place

In a Redline round, a plan the plan approver bounces goes back to the shaper as a reshape (label `reshape r<n> #<k>`). Its prompt says to read the spec folder's four files, correct them in place, and keep every decision the person made or the autopilot applied. When that reshape stops at stage `shape`, the relaunch resumes at it, and `resumeLine` in `workflows/redline-loop.js` appends the shaper's resume sentence: "Rewrite plan.md, shape.md, standards.md and references.md in the spec folder from scratch, replacing what the earlier attempt wrote". The stop can be a missing `shape.md` or `## Decisions` section, a decline with no reason, a deferral with no drafted issue, or a `why_human` outside the round's cases. In a round where the person or the autopilot decided a finding, the folder by then holds the entries and tasks the resolve agent wrote for those decisions, each ending `Decided by: @<login>` or `Decided by: redline (autopilot)`. So the rerun is told two contradictory things, and a rewrite can drop the record of the person's decision and the task planned for it. Only a stop whose error opens `the reshape left ` gets the sentence that says to correct the task in place. A resume keeps the last error, so a reshape resumed after that stop that then fails another check is told to rewrite on its next resume. A decided fix that loses its task is caught again by the hold after the reshape, and nothing checks that `shape.md` still records the decision.

- **Where:** `workflows/redline-loop.js:592`
- **Why it is not fixed in #114:** The rewrite sentence, and its use on every shaper resume, predate the pull request this was found in. That pull request added only the narrow exception for its own new stop and recorded the rest as left alone in its spec ("The shaper's resume line on other reshape stops ... Not changed here"). Widening it changes the resume prompt of every reshape stop, needs wording that fits each stop's error rather than "the task the error names", and changes a loop case that pins today's sentence.
- **Proposed fix:** In `resumeLine`, give a shaper resumed at a reshape label (`opts.label` starting `reshape `) a sentence that says to read the four files as the earlier attempt left them, keep every entry the person or the autopilot decided and the tasks written for them, correct what the error names, and return the whole result again. Keep the rewrite sentence for the first shape of a round (`shape r<n>`, `shape h<n>`), which runs before any decision, and keep the hold's own clause or fold it into the new one. Update rule 9 of `agents/redline-shaper.md`, the replay standard's resume clause and `docs/running.md`. Change the loop case `a reshape resumed after another stop keeps the shaper's own resume line` to expect the new sentence, beside a case where the first shape's resume still rewrites.
