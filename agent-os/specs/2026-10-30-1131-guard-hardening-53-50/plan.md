## Context

Two issues, both guard holes found by review, both deferred to a person because the guard is a person's file.

- **#53** (from #52 R1-1): `writable()` cuts a Bash write target at its first `*` or `?` (`scripts/redline-guard.sh:406`) and checks only the prefix; `[...]` and `{a,b}` are not cut at all. So a Redline role can `sed -i` `scripts/redline-guar?.sh`, `hooks/hook*.json`, `.claude/settings*.json`, `.claude/{redline,x}.json`, or a file under a `paths` ask rule. The blunt fix: a Bash write target holding `*`, `?`, `[` or `{` is refused for every role unless it is under the temp directory. No expansion at check time: a pattern that matches nothing yet is admitted when an earlier part of the same command creates the match.
- **#50** (from vestmark-com#13): (1) the template's `Bash(/*/scripts/redline-gh.sh *)` rules match a script of that name at any path, so an agent can write one under a path it may write and run it unprompted; (2) `git diff/log/show --output=<file>` writes a file, `git -c diff.external=…`, `git grep -O…` run a program, both through the template's `git …:*` rules and through the guard's `check_git`, which reads no flags; (3) setup writes model IDs into `redline.json` while the CLAUDE.md paragraph it adds does not say that is allowed; (4) `checks.sh` dies without JSON when an untracked file cannot be `cat`ed (a symlink to a directory).

## Decisions

1. **#53, the blunt fix.** In `writable()`, a **Bash** write target holding `*`, `?`, `[` or `{` is refused for every role unless its literal prefix (cut at the first of those) is under the temp directory and the role has `TMP`. The prefix still goes through `protected()` and `ask_rule()` first, so an operand already inside a protected directory or a rule's root keeps its specific reason (row 458). The reason names what the pattern could reach when the prefix is a string prefix of a protected pattern's path (`scripts/redline-guar` → `scripts/redline-guard.sh`; `.claude/settings` → `.claude/settings*.json`), of a rule's root (`config/proj` → `craft-config`), or when a rule has no literal root (`yaml-anywhere`), else says "name the file". (Settled while shaping, so the flipped rows can name the rules as decision 1 asks.) **A tool `file_path` (Write, Edit, MultiEdit, NotebookEdit) is literal and is no longer cut:** `Write app/pages/[id].php` is the file of that name, pinned by a row. `sed -i '' … tests/*.sh` is refused; the implementer names files, and its prompt says so.
2. **#50 part 1** as proposed. The guard, for a call whose `agent_type` is not a Redline role (the main session, any other agent), approves a Bash command when every simple command in it is one of: the plugin's `scripts/redline-gh.sh` (any subcommand), `scripts/redline-prefs.sh` (any), `scripts/redline-gate.sh check`, `scripts/redline-setup.sh version`, the repository's `.claude/redline/checks.sh` (any arguments, a `REDLINE_OCTANE=1` prefix allowed), each resolved by realpath, or read-only git under decision 3's vetting; `cd` and `VAR=value` prefixes pass as they do for roles; a write target other than `/dev/null` is not approved. **Anything else leaves the guard inert, never a deny**: the normal permission prompt applies. The reserved subcommands (`gate stamp`, `setup settings|config|checks|…`) stay behind the prompt, as the bash-conventions standard says. The bash fast path lets a non-role Bash call reach Python only when the command mentions `redline-(gh|prefs|gate|setup).sh`, `checks.sh` or a `git` word, so other sessions pay nothing. The seven entries leave `templates/settings.allow.json`; the relative `checks.sh` rules, `git status/rev-parse/merge-base`, `Workflow(...)` and `Edit(/agent-os/specs/**)` stay.
3. **#50 part 2, answered today: refuse all.** `check_git` refuses, for every subcommand and every role, the global options `-c`, `--config-env`, `--exec-path`, `--git-dir`, `--work-tree`; and for every `GIT_READ` subcommand the flags `--output`, `--output=…`, `-O…`, `--open-files-in-pager…`, `--ext-diff`. `check_simple` refuses any `GIT_*` or `PAGER` environment prefix (bare or via `env`) on a `git` command. Rows for the reviewer and the plan-approver (and one `-c` row for the github role); plain `git diff HEAD~1`, `git log -1`, `git grep -n foo`, `git -C <repo> status`, `git --no-pager log -1` stay allowed.
4. **#50 part 3.** The sentence "Configuration that selects a model, such as `models` in `.claude/redline.json`, is not attribution and is allowed." is appended to the paragraph in `templates/claude-md-git-sentence.md`; the setup skill's step 11 appends it in place on a rerun that finds the paragraph without it; this repository's own `CLAUDE.md` gets it now (the dogfood rerun).
