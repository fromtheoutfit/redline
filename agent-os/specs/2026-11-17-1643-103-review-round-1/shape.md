## Deferred

### R1-9: Count a deferred draft's version over what its stop shows, so a change to what ships is raised again

- **title:** Count a deferred draft's version over what its stop shows, so a change to what ships is raised again
- **found:** At a Redline stop each deferred draft is shown with `ships`, `files` and the mitigation's words beside the issue text, but its version (`draftsOf` in `workflows/redline-loop.js`) counts only the issue text that `issueDraft` composes (the title, what was found, the place, why it is not fixed and the proposed fix), and an answer covers every version up to the one it named (`draftAnswered`). So when a reshape after a bounced plan changes only a deferral's `files` or its mitigation words, an answered draft is not raised again: a person who let a draft go ahead when it was shown with `ships: false` is never told that a mitigation now ships, and the build commits it and the reply reads `Mitigated in ...`. The gap is as old as the version: a reshape that rewrote the mitigation words had it before `ships` and `files` were shown.
- **why:** The version is defined over the issue as it will be filed (the workflow/replay standard and the comment above `draftsOf`), and that guarantee still holds in this case, since the filed text is unchanged; counting what the stop shows changes when a person is asked again, a change to the stop's contract that goes beyond reading a deferral's mitigation from the round's record.
- **fullFix:** Keep a second fingerprint beside `text` in `record.drafts[id]`, built from the files and the mitigation words the stop shows, and raise the version when either changes; reword the replay standard's line on versions and the comment above `draftsOf` to say a version counts what the stop shows; add a loop check that lets version 1 go ahead at a stop showing `ships: false`, bounces the plan, has the reshape list files, and expects a second stop for the draft.
- **mitigation:** none (nothing ships now).

### R1-4: List every finding's files in the unattended section's return example

- **title:** List every finding's files in the unattended section's return example
- **found:** The shaper's output schema in `workflows/redline-loop.js` requires `files` on every finding since a deferral's mitigation is read from the round's record, and the shaper's agent file shows it on every finding of its example, but the return example in point 10 of `templates/shape-spec-unattended.md` (and this repository's copy in `.claude/commands/agent-os/shape-spec.md`) shows no `files` on any finding, and the sentence under it that lists what every finding carries leaves it out. - **why:** The pull request that made `files` required kept the template as it is on purpose, as a patch release with no setup rerun, since the workflow's prompts and the shaper's agent file ask for `files`; a template change is a minor bump with a new section marker and a setup rerun in every repository, which belongs with the next change to the section.
- **fullFix:** In `templates/shape-spec-unattended.md`, add `files` to every finding of the point 10 example as `agents/redline-shaper.md` shows it (the fix and the mitigated deferral with their paths, the ask and the decline with an empty list) and to the sentence under it; bump the section marker and the minor version, freeze the previous body under `templates/history/` and pin its hash in `tests/setup-test.sh`, and rerun setup so this repository's copy carries the new body.
