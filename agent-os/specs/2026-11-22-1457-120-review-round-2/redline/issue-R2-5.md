# Tell a reshape whose Writes were refused from one that rewrote its spec folder

After the shaper returns, the workflow's spec check (`checkSpec` in `workflows/redline-loop.js`, through the GitHub agent's read-only `spec-status` operation) lists the round's four spec files and greps `shape.md` for its `## Decisions` heading, so it sees a refused Write only where the Write would have created a file, which is a round's first shape, whose folder holds only `redline/` before the shaper runs. At a reshape after a bounced plan (`reshape r<n> #<k>`), `plan.md` and `shape.md` are already on disk from the first shape and the resolve, so a reshape whose Writes were all refused passes the check. When its result then fails one of the shaper's result checks (a finding with no disposition, an ask with no judgment call, a decline with no reason, a deferral with no drafted issue) or the hold of a decided finding to its task, the stop carries `ownCheck` true and the skill tells the person that nothing needs fixing by hand, so they relaunch without allowing the Writes (the harness refuses a subagent's Write in auto mode when the plugin is loaded with `--plugin-dir`, #76) and the rerun's Writes are refused again. A reshape whose Writes are refused and whose result passes every check goes unseen as well: the plan approver is shown the plan as it stood before the reshape, bounces it again, and the run stops at the approve cap. A resumed first shape whose earlier attempt wrote the four files is in the same position.

- **Where:** `workflows/redline-loop.js:3819`
- **Why it is not fixed in #120:** The pull request that found it (#120, review round 2 of #117) marks the shaper's result checks as the workflow's own check and runs the spec check before them, which is right for every attempt that leaves a file out; the spec check's existence test is older (#57), and telling a refused Write from a rerun that rightly changes no file needs a design of its own, since a reshape resumed after a check of its result may correct only what it returned and write nothing. The launch skill already tells the person, before every resume from a session that loads Redline from a directory, that auto mode refuses the agents' writes, which covers the known cause, and the pull request records the limit in `docs/running.md` and the comment on `vetShape`.
- **Proposed fix:** Have the `spec-status` operation print a fingerprint of each of the four files (`git hash-object`, read-only), read it before and after a reshape and a resumed shape, and treat a call that was asked to write and changed no file as a spec-check stop with no `ownCheck`, so the skill says to fix the cause first; decide first which calls must change a file (a reshape after a bounce applies each adjustment or records in `shape.md` why it cannot, so it always writes; a rerun after a check of its result may not) and what the extra read costs the prompts of a run with no refusal. Add loop-test cases, seen red first, for a reshape whose Writes are refused beside a result check and beside a passing result, with a reshape that writes as the neighbour, and update `docs/running.md` ("Run markers and resume") and the comment on `vetShape`.
