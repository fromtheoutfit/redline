## Context

Spike #72 (PR #78) answered **spec it**: on Losers League #817 at its pre-Redline SHA, today's reviewer reported three confirmed findings and none of the teammate's seven primary items; the built-in `code-review` skill, run from a default workflow subagent at the same model and effort, reported seventeen with no false finding, a strict superset. The union is the skill's list; what Redline adds is the contract (collapse by cause, known-finding check, reproduction, ids, severities, a line inside the diff, ask rules, carry-forward). So the skill becomes the **finder** and Redline's reviewer the **verifier**. The fix-diff recheck of the previous round's fixes stays as it is, and the final nit pass is unchanged.

**Revised on 2026-11-05, before Task 4, for the issue's changed body.** Two decisions, already made (Decisions 20 to 22): the coverage pass runs on the whole PR at the round's head on **every round**, not only round 1, because the teammate's extra findings on #817 and #778, the keys the spike and Task 2 measured recall against, were `/code-review` run again on later SHAs: the skill is stochastic and attends to what moved, so each pass is a sample, and the manual loop stops when a pass confirms nothing new; and the run's **done rule** becomes that loop's: the run finishes when a round's verifier confirms no new correctness finding, where new means not collapsed into a known, dispositioned or carried finding, under `maxRounds`, the final nit pass unchanged. The skill never returns an empty list, so the stop rule is the verifier's, with two guards in its rules (a candidate anchored outside the diff is never a finding; a candidate that needs implausible conditions to bite is disproportionate and is dropped with that word). The verify-only decision of Task 3 stays and now applies to every round's verify call.

The spike's evidence is one PR, so the first task is a second corpus PR, and its decision rule picks between **verify-only** (the verifier replaces the reviewer's discovery pass) and **union** (both passes in parallel, the verifier merging both lists). The three harness facts the design builds around are now in `agent-os/standards/`: the guard does not see a skill fork (`scripts/guard.md`); a role launched with a `schema` swallows the skill's output (`workflow/agents.md`); the run record counts the calling agent only (`workflow/agents.md`).
