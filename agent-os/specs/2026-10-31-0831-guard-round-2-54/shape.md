# Guard: the round-2 findings on PR #54 — Shaping Notes

## Scope

The eight correctness findings of Redline round 2 on PR #54 (review 5718692837, 2026-10-30), all in `scripts/redline-guard.sh`, a file only a person changes. R2-2, R2-3, R2-6, R2-7 and R2-8 are round-1 findings (review 5715390081) carried forward; round 1 landed nothing on the branch, so there is no row to flip and no Known limits bullet to remove. Person-led: shaped with `/agent-os:shape-spec` in a normal session, the person making every commit. One sentence per finding, the gap and the refusal that closes it:

- **R2-1** · the main-session approval reused the role vetting, which passes `cd`, every builtin, `find` and `sed` before it looks at a group; the approval now covers only the plugin's scripts, the repository's `checks.sh` and read-only git, as bare command words. For the roles, a sed script's `w`, `W` and `e` commands and `s///`'s `w` and `e` flags, and find's `-fprint`, `-fprint0`, `-fprintf` and `-fls`, write or run through text the guard never read; they are refused for every role.
- **R2-2** · the sed branch passed the script after `-e` to `writable()`, so a regex holding `*` or `[` was refused as a pattern; the script and the file after `-f` are no longer write targets.
- **R2-3** · a pattern under the temp directory was admitted on its literal prefix, and `..` segments after the wildcard climbed back into the repository; a pattern with a `..` segment is refused, and the exemption holds only when the wildcard is in the last segment.
- **R2-4** · a file whose name holds `[` or `{` could be edited but never staged; `git add` of a path that names an existing file exactly, and is not protected, is allowed.
- **R2-5** · `!` and the shell keywords were builtins, so the word after them was never checked; they are refused as a command word.
- **R2-6** · a `GIT_*` prefix was refused only directly on git, while `export`, `bash -c`, `env`, `BASH_ENV` and `PATH` reached git and the approved scripts; every route that sets a variable for a child is refused, with two exempt names.
- **R2-7** · `-O` on git grep was refused only at the start of a word and `--open-files-in-pager` only spelled out; a bundle holding `O` and any `--op` abbreviation are refused.
- **R2-8** · `git -C <dir>` and `cd <dir> && git` ran git in a repository whose `.git/config` could name a program; git runs only at the repository root.

## Decisions

Decisions 1, 2 (its first clause), 4 to 13 were given by the person in the shaping prompt on 2026-10-31; the questions put during shaping are marked; the refinements the session settled from the code are marked and were confirmed at plan approval.

1. **Refuse the class, never a list of cases**, as PR #54 does for wildcards and `git -c`. Decided by: @michaelwitwicki.
2. **R2-1, the main session.** The approval covers only the plugin's scripts by real path, the repository's `checks.sh` and read-only git, each as the bare command word (no wrapper, `timeout`, `xargs` or `env`), plus `cd`, whose result the git root rule of decision 7 vets. Any other command word leaves the guard inert, so the permission prompt decides. The bare-word clause: refinement from the code (`check_simple` strips wrappers before it looks at the word), confirmed at plan approval. Decided by: @michaelwitwicki.
3. **R2-1, the roles: its own ninth commit** (shaping question 1, answered 2026-10-31). A sed script (positional, after `-e` or `--expression`, in `--expression=`, or the file after `-f`, read as `git commit -F` reads its file) holding a `w`, `W` or `e` command, or a `w` or `e` flag on `s///`, is refused for every role; a find predicate that writes a file (`-fprint`, `-fprint0`, `-fprintf`, `-fls`) is refused. The script is read as sed reads it: addresses, one command letter, the bodies of `s` and `y` skipped by their delimiter, the labels of `b`, `t`, `T` and `:` skipped, the text of `a`, `i` and `c` to the end of the line; a script the reader cannot place is refused, which is the guard's default. Decided by: @michaelwitwicki.
4. **R2-5.** `!` and every shell keyword (`if then else elif fi for do done while until case esac in select function coproc`) are refused as a command word for every role and inert for the main session; they leave `BUILTINS`. A role runs plain pipelines, which the agents' Bash rules already say, so the reviewer's proposed "keep" rows (`if git diff --quiet; then …`, `for f in a b; do …`) are deny rows beside the pipeline spelling. Decided by: @michaelwitwicki.
5. **R2-6** (shaping question 2, answered 2026-10-31). `export`, `declare`, `typeset`, `set`, `readonly` and `local` are refused as commands for every role (they leave `BUILTINS`; `unset` stays). A `NAME=value` prefix, bare or through `env`, on any command word is refused unless NAME is `REDLINE_OCTANE` or the `env` of a `vars` entry in the repository's `.claude/redline/checks.json` (a file that cannot be read declares nothing), and the value is a plain word after the shell's quoting: letters, digits, `_`, `.`, `/` and `-`, so no `$`, backtick, quote or space. Every `env` option is refused (`-C` and `-S` change what runs). The git-only `GIT_*`/`PAGER` check is subsumed and its reason now names the variable, so the fifth-column rows stay green. Rows 103 (`DB_DATABASE=… php artisan migrate`) and 297 (`TMPDIR=/tmp git status`) flip to deny; the declared-var allow runs in the ask-rules fixture, which gains a `checks.json` with one var. Decided by: @michaelwitwicki.
6. **R2-3.** A pattern write target with a `..` segment anywhere is refused for every role, and the temp-directory exemption holds only when the text after the cut holds no `/`: the wildcard is in the last segment, so it cannot match a symlink that is then walked through. The symlink half is the finding's second clause, taken as part of the same class (a pattern whose expansion can leave the temp directory); refinement confirmed at plan approval. Decided by: @michaelwitwicki.
7. **R2-8, option A from round 1.** After `-C` and any `cd`, the resolved working directory of every git subcommand must be the repository root (`REPO` or `REPO_REAL`); otherwise refused for the roles, inert for the main session. Applied to every subcommand, not only the read ones, since the config route reaches them all; `git -C <repoRoot> …` and `cd <repoRoot> && git …` resolve to the root, so the github role's record-commit rows and the skill's main-session calls stay approved. Consequence: a run launched from a subdirectory (the skill's section 1 requires only "inside the checkout") would see every role's git refused; the README's Launching section now says to launch from the repository root, and the skill precheck is listed under Deferred. Decided by: @michaelwitwicki.
8. **R2-7.** On a read subcommand, any single-dash word whose letters hold `O` and any word starting `--op` (every abbreviation git's parse-options accepts for `--open-files-in-pager`; no other read option starts that way) are refused, beside `--output`, `-O…` and `--ext-diff`. A flag is read as git's parser reads it, bundles and abbreviations included, for every read subcommand. Decided by: @michaelwitwicki.
9. **R2-2.** In the sed branch the word after a detached `-e`, `--expression`, `-f` or `--file` is the script or a script file, never a write target; `writable()` sees the file operands only. A row pins a regex holding `*` and `[`. Decided by: @michaelwitwicki.
10. **R2-4.** `git add <path>` with a path holding `*`, `?`, `[` or `{` is allowed when a file of exactly that name exists (no expansion) and the literal path passes the protected and ask-rule checks; when no such file exists the path is a write operand and the pattern refusal applies. The add branch's own `*`/`?` refusal is replaced by this rule. Noted, not changed: git's own pathspec matching reads `[id]` as a class too, so the add may also stage a modified sibling `i.php` or `d.php`; harmless, since the role could stage it by name and the checker's allowed list catches a file the plan did not name; `git --literal-pathspecs add` passes the guard for a role that wants exactness. Decided by: @michaelwitwicki.
11. **Rows.** Every refusal gets a deny row beside its literal neighbour in `tests/guard-cases.tsv`, in the same commit as the guard change; `tests/guard-test.sh` green after each commit. Decided by: @michaelwitwicki.
12. **Order, one commit per finding:** R2-1 (main), R2-5, R2-6, R2-3, R2-8, R2-7, R2-2, R2-4, then R2-1 (roles) ninth. The spec folder is committed first; the standards commit and the as-built commit follow. The person titles every commit. Decided by: @michaelwitwicki.
13. **Docs.** The README's guard section says what the guard refuses, in one list. Decided by: @michaelwitwicki.
14. **Standards carried: six** (shaping question 3, answered 2026-10-31): `scripts/guard`, `scripts/bash-conventions`, `testing/tests`, `process/docs-gate`, `process/standards-retrospective`, `prompts/attribution`. Not carried: `workflow/agents`, `workflow/replay`, `process/internal-notes` (no prompt, workflow or design-note change). Decided by: @michaelwitwicki.
