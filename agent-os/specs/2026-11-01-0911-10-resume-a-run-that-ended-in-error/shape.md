# Resume a run that ended in error — Shaping Notes (#10)

## Scope

The first two bullets of issue #10, as written there, read with the eight decisions of the shaping prompt and the four answered on 2026-11-01:

- A run that ends in `error` leaves a relaunch marker, the same one every other stop leaves (a hand-off, the review dial, a run the harness stopped), and the next `/redline:redline <pr>` offers to resume it or start fresh, naming the stage and the error. Resume replays the finished agents from cache and reruns from the failed step.
- Resume checks the session, the branch, HEAD (equal to the run's last commit, or on top of it with hand commits that touch only `.claude/` paths, which the checker then treats as pre-existing), the plugin case, and that the only untracked or modified paths are under the run's spec folders.
- In passing: `review only` and revise-only runs end with the run-record commit, and every `done` result carries `handoffPosted` and `reviewRequested` as booleans.

**Dropped as already done.** The issue's third bullet (a fresh launch numbers its first round after the last posted one and posts its review) landed with #33 and #35: `skills/redline/SKILL.md` precheck steps 8 and 9 (`last-round`, `prior-findings`), `args.firstRound` in `workflows/redline-loop.js`, the GitHub agent's per-round `has-review <n> <round>` check, and `tests/loop-test.mjs` section 8 (`firstRound 2`, `has-review 114 2`). The "same round number *and* same findings" refinement of the "already posted" skip is moot: a fresh run always gets a new number, a relaunch replays post from cache, and a resume at `post` reruns the agent whose has-review check skips the already-posted review.

**Not built here: #57.** Its check (the shaper's result has a spec folder with `plan.md`, a `shape.md` holding `## Decisions`, and one entry per finding) needs a new read-only GitHub-agent operation, a prompt function, a loop-test mock branch, a role-file change and a README line: more than one task. It stays its own issue. What this spec gives it: a shape-stage error already carries `resumeFrom: {label: "shape r<n>", attempt}` and resumes by rerunning the shaper with the replace sentence (decision 4), so #57 only has to raise the error.

## Decisions

The prompt's eight stand as given; four were put to the person on 2026-11-01, one at a time, and answered as recorded; the rest were made from the survey.

1. **Marker** (prompt 1): one marker for every stop: run id, kind (`error`, `handoff`, `reviewed`, `stopped`), stage, the agent label and next attempt, the error text, HEAD, branch, the session id, the harness record's path, the spec folders and the args as launched. The skill offers resume or fresh with the stage and message in the question. Decided by: @michaelwitwicki.
2. **Session** (prompt 2): resume needs the session that launched the run (the harness replays from its saved results, same session only). The check prints `claude --resume <session id>` and the skill shows it and stops, rather than relaunching into "nothing to resume". Decided by: @michaelwitwicki.
3. **HEAD** (prompt 3): as the issue states it, plus the plugin case: HEAD equal to the marker's, or on top of it with hand commits that touch only `.claude/` paths; untracked or modified paths only under the run's spec folders; when the repository under review is the plugin itself (`repoRoot` resolves to `${CLAUDE_PLUGIN_ROOT}`), any moved HEAD refuses with "start fresh: the next round carries the findings forward", since a plugin fix changes what runs. Decided by: @michaelwitwicki.
4. **Shape stage** (prompt 4): a resume at a shape-stage error (today: a missing disposition; #57's case once a missing spec is an error) reruns the shaper. Its resume line says to rewrite `plan.md`, `shape.md`, `standards.md` and `references.md` from scratch and never to change or remove anything under `redline/`, so the record folder of the failed attempt is replaced, not appended to. Decided by: @michaelwitwicki.
5. **Record commits** (prompt 5): `review only` and revise-only runs commit their record at the end like a full run, so an error after them leaves nothing untracked and the next launch's clean-tree precheck passes. The `handoffPosted` null: the revise-only and human-review `done` results carried no `handoffPosted` key, so the skill's `done` report read null. Offered: the absent key (recommended); a null from the Finish agent; drop it. **Answer: the absent key.** Every `done` carries `handoffPosted` and `reviewRequested` as booleans, `false` where no handoff was posted, with a loop-test check per path. Decided by: @michaelwitwicki.
6. **#57** (prompt 6): not built here; see Scope. Decided by: @michaelwitwicki (the rule), redline (the fit).
7. **Tests** (prompt 7): the issue's list plus the session-mismatch refusal, the plugin-HEAD refusal and the shape-stage resume. The git checks are proven in `tests/prefs-test.sh` (the script runs them), the replay, the resume line, the rerun and the record commits in `tests/loop-test.mjs`. Decided by: @michaelwitwicki.
8. **Docs** (prompt 8): README Launching and Known limits, plus Saved preferences, the Files table, Git rules 1 and 7 and the Use paragraph, which the record-commit change makes wrong. Decided by: @michaelwitwicki.
9. **Marker home.** Offered: a `runs` map keyed by PR in `.claude/redline.local.json` through new `redline-prefs.sh run save|read|check|clear` subcommands (recommended); a new `.claude/redline-run.local.json` with its own script (a guard approval line, a second gitignore line from setup, a new harness); a file outside the repository under `~/.claude/redline/runs/`. **Answer: the recommended option.** The file is already gitignored, refused to every role, approved for the main session by real path with any subcommand, and tested; `save` is taught to keep the other keys. No guard, gitignore or setup change. Decided by: @michaelwitwicki.
10. **Resume mechanics.** The docs confirm a completed agent replays its cached result even when the script threw after reading it, so a plain relaunch repeats the error. Offered: a label-keyed resume line (recommended); a stage-keyed line on the stage's first agent; the label-keyed line with the HEAD check inside the workflow through an agent call at the resume point. **Answer: label-keyed.** The error result names the agent label that caused the stop; the relaunch adds `args.resume = {"<label>": {attempt, error, hand}}`; `run()` appends one resume line to that label's prompt. Everything before replays byte-identically; that agent and all after rerun. The prefs script does the git checks before launch, as the precheck does for a fresh launch. A hand commit's `.claude/` paths and SHAs ride in `hand`: the judge excuses the paths and the commits, and the paths join `approvedPaths` at the resume point, never at startup, since a startup seed would change the cached snapshot prompt and rerun the implementer over commits it already made. Decided by: @michaelwitwicki.
11. **Standards carried.** Offered: seven (recommended); five without bash-conventions and attribution; eight with internal-notes. **Answer: seven**: `workflow/replay`, `workflow/agents`, `scripts/bash-conventions`, `testing/tests`, `process/docs-gate`, `process/standards-retrospective`, `prompts/attribution`. Decided by: @michaelwitwicki.
12. **Not resumable**: a `gather` error (head moved since launch, PR not open, wrong head branch) and an error with no agent label. The error result's `resumeFrom` is null, `run save` writes no marker (exit 1 with the folders to commit or remove), and the skill says fresh is the only path. Decided by: redline.
13. **The marker reads the harness record**, not the skill's memory: `run save` takes the run id, finds `~/.claude/projects/*/<session>/workflows/<runId>.json` (or `--record <file>`), and copies `args` and the result's fields from it, so a resumed session relaunches the args the harness ran, byte for byte. The script reads the session id from `CLAUDE_CODE_SESSION_ID` itself (set in every Bash tool subprocess), so the skill never types a `$`. Decided by: redline.
14. **One record-commit message** for every run kind, as the README and the loop test pin it. A review-only record holds reviews and findings only, which "replies ... and handoff" overstates; kept for one message everywhere. Decided by: redline.
15. The person makes every commit. Visuals: none.
16. **Standards retrospective: applied** (2026-11-01): the three edits under "Standards retrospective (applied)" below; `scripts/bash-conventions.md` was already covered. Decided by: @michaelwitwicki.
17. **As built, four deviations from the plan** (see `plan.md`, As built): the start snapshot's folder is read off the record's `args.repoRoot` and the snapshot's fixed tail, never by splitting on `/redline/` (the rehearsal on a real record found the stray folder; pinned red before green); the loop test's record-commit tail check takes the step each run kind ends with (`post` for review only, `push and reply` for revise only), and the review-only "three calls" pins became five; the new loop checks guard their `pick()` calls so the red run reports instead of crashing; the Approve stage's "returned nothing" error names the approver that returned nothing. Decided by: redline.

## Standards retrospective (applied)

Proposed at shaping, presented at the gate on 2026-11-01 and approved as proposed (decided by: @michaelwitwicki); the three edits landed in the standards commit. One check went red during the build and was fixed by learning something: the prefs case for a repository path holding `/redline/`, recorded in the tests standard. No pattern was used that is not in `agent-os/standards/`.

- `agent-os/standards/workflow/replay.md`: add a bullet: "A resume after an error changes exactly one prompt: `run()` appends a resume line to the agent label the error result's `resumeFrom` names (`args.resume`), so every prompt before it replays and that agent and all after rerun; a cached result the script rejected replays unchanged on a plain relaunch, which is why the line exists. A hand commit's paths join `approvedPaths` at that label, never at startup, so the cached snapshot prompt stays byte-identical (#10)".
- `agent-os/standards/workflow/agents.md`: add a bullet: "An error result names the agent label that caused the stop (`resumeFrom`), and the skill writes a marker through `redline-prefs.sh run save`; a resume is the person's choice at the next launch, never a retry by the skill or the workflow, and a `gather` error is not resumable (#10)".
- `agent-os/standards/testing/tests.md`: the prefs-test bullet gains "and the run marker (`run save|read|check|clear`) with every refusal (session, branch, head, plugin, untracked) in a throwaway git repository there, on records whose repository path holds `/redline/` as this checkout's does (#10)"; the loop-test bullet gains "a resume scenario proves the error result's `resumeFrom`, the byte-identical prefix up to the resumed label, the resume line on that prompt alone, a shape-stage rerun, an excused hand commit beside an unexcused unexpected file, a non-resumable gather error, and the record commit that ends `review only` and revise-only runs (#10)".
- `agent-os/standards/scripts/bash-conventions.md`: already covered (one JSON object on stdout, usage errors exit 2); no edit.

## Standards Applied

- workflow/replay — the resume line is the one prompt change on a resume, and the hand paths enter at the resume point so the cached prefix stays byte-identical
- workflow/agents — the error result names the label; the skill never retries; owners unchanged
- scripts/bash-conventions — the prefs script's new subcommands print one JSON object, exit 2 on usage, and run read-only git
- testing/tests — the prefs cases and the loop checks land red before green, with a neighbouring case for the decision that must not change
- process/docs-gate — the plan carries a Docs entry per touched file; the README sections are named
- process/standards-retrospective — the proposed edits above are presented at the gate and land in their own commit, or "no changes" is recorded
- prompts/attribution — the spec folder, the resume line, the marker and the commits carry no model or vendor name
