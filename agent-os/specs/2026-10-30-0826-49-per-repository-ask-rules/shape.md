# Per-repository ask rules — Shaping Notes (#49)

## Scope

`.claude/redline.json` gains `askRules`, a list of `{id, when, reason}` where `when` is `{"paths": [globs]}` or `{"prose": "<sentence>"}`. A finding a rule covers is the person's to act on: `ask` with `why_human: "repository rule <id>"`, never `fix` or `defer`, left to the person on autopilot with no change made. Paths rules are enforced twice, by the guard (a write to a matching path is refused for every role, naming the rule) and by the workflow (one forcing function sets `ask` whatever the shaper returned). Prose rules are judged by the shaper and checked by the plan approver from a rule list the workflow injects at launch. The reviewer gets the list too and tags a finding it covers (advisory). The review marks a rule-matched finding, the hand-off presents it as the person's, the reply says `left to the author under repository rule <id>`, the handoff comment lists it under its rule id, and its thread stays open. `/redline:setup` asks for ask rules, suggesting the Craft project-config rule and the Laravel migrations rule from `composer.json`, and carries them through unchanged on a rerun.

Not in scope: numeric limits (#25, which shares the forcing point), per-stack default rules (#3), a rule that covers Redline's own spec folder (documented as not to be written).

## Decisions

The shaping prompt's thirteen decisions stand as amended below. Each answer was given by the person on 2026-10-30; the rest were settled from the code while shaping.

1. **`askRules` shape** as specified, with one validation wording shared by the skill's precheck, `redline-setup.sh config --ask-rules` and the guard: `id` matches `[a-z][a-z0-9-]*` and is unique; `when` holds exactly one of `paths` (a non-empty list of non-empty strings, no `!`, no `[`) or `prose` (a non-empty string); `reason` is one non-empty line. Absent or `[]` is today's behaviour. Decided by: redline (from the prompt's decision 1).
2. **Outcome kind `left`.** A rule-matched finding is never `fixed` or `deferred` in the run's records: it has its own outcome, `left`, so no commit is demanded (`needCommits`), the thread sweep leaves it open, and a human review pass's refusal of `defer` is never tripped. Guided: the person's answer is recorded `decided by: @<login>`; the options are the person's to carry out outside the run ("Make the change by hand after the run", "Accept, no change"), since the guard refuses the write anyway. Autopilot: `decided by: redline (autopilot)`, no task, no commit, recorded under Deferred with `mitigation: none (repository rule <id>)` and the shaper's recommendation as the full fix, as the prompt's decision 2 asks. A plan-dial override to `fix` or `defer` on such a finding is refused with a warning. Decided by: redline (the prompt's decision 2, given a shape the code can carry).
3. **One glob dialect in the guard (Python) and the workflow (JS)**, pinned by the same cases: matched case-folded against the repository-relative path; `**` spans segments; `*` and `?` stay inside a segment; a pattern with no `/` (a trailing one aside) matches at any depth; a leading `/` only anchors; a trailing `/` matches the directory and everything in it; no negation, no classes. The guard also refuses a directory target that holds a rule's root (`rm -rf config`; `sed -i … config/project/*.yaml`, which the guard cuts at `*`). The target is always realpathed (non-strict, so a missing parent no longer skips resolution) and the repository root is realpathed for the relative path, so a symlink inside the repository and one under the temp directory that resolves into a match both refuse. A malformed list makes the guard refuse every write by a Redline role, naming the fault (fail closed). Decided by: redline.
4. **Rule source: `args.askRules`.** The workflow has no filesystem and reads nothing but `args` (`workflows/redline-loop.js:28`, `skills/redline/SKILL.md:100`), so the skill reads the list from `redline.json` at each fresh launch and passes it; the workflow injects it into the prompts. A rule edit needs no setup rerun, only a new launch; a relaunch keeps the rules the run started with. The `why_human` value `repository rule <id>` is listed in the shaper's agent file, the unattended template and this repository's copy (outside the gate, so no restamp); the schema's enum is built from the rules. **Decided by: @michaelwitwicki** (the prompt said "injected by the workflow from `redline.json`"; the mechanism was confirmed).
5. **The forcing point** is `forceAskRules(record, pass, inScope, shaped)` in `workflows/redline-loop.js`, run right after `checkDispositions` on every shape and reshape, commented as the function #25's numeric limits share. It matches a `paths` rule on the finding's own file, then on the files the shaper's JSON lists for it (a new `files` field), then takes the shaper's `askRule` tag. Decided by: redline (the prompt's decision 5).
6. **The review mark.** The reviewer's prompt gets the rule list and the reviewer may tag `askRule: "<id>"`; the tag is advisory: the shaper still applies the rules and the forcing point wins. The mark is both the finding line's last tail (` · yours under rule <id>`, which `redline-gh.sh prior-findings` strips from the title) and a sentence in the inline comment ("This one is yours to act on: repository rule <id> (<reason>)."). A paths match on the finding's file marks it whatever the reviewer returned. **Decided by: @michaelwitwicki** (two answers).
7. **Handoff.** A `### Left to you (repository rules)` section, the Deferred line variant for autopilot entries, the threads line naming them as open with reason `repository rule <id>`, and a "left to you" part in the human review summary. Decided by: redline (the prompt's decision 7).
8. **Setup.** A read-only `redline-setup.sh suggest-ask-rules <repoRoot>` prints the stack suggestions from `composer.json`, so the Craft suggestion is testable in `tests/setup-test.sh`; `config --ask-rules <file.json>` validates and writes the list; without the flag an existing list is kept and printed; `config_differs` ignores `askRules` so a rerun's `differs` does not list the person's rules as drift. The skill asks in step 7 after the reviewer question. The template `redline.json.example` does not gain the key: the key is optional, and `tests/setup-test.sh:179` pins a fresh write byte-identical to this checkout's `redline.json`. Decided by: redline (the prompt's decision 8, made testable).
9. The guard keeps refusing `.claude/redline.json`. Decided by: redline.
