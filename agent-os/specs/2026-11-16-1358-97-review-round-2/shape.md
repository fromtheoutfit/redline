### R2-15: Have the resolve agent name each decision's disposition, so a stray deferred entry beside a fix is not filed

- **Mitigation (ships now, Plan Task 12):** `resolvePrompt`'s calls block in `workflows/redline-loop.js` says, beside the decisions, that a deferred entry is returned for a call only when its decision defers the finding (a "mitigate" choice, or the person's own words saying to defer it), and that a decision that fixes the finding in full or accepts it returns none; a key-phrase check in `tests/loop-test.mjs` pins it on the resolve prompt of a run with a call.
- **Title:** Have the resolve agent name each decision's disposition, so a stray deferred entry beside a fix is not filed
- **What was found:** When a person, or autopilot, decides a judgment call, Redline learns that the decision deferred the finding only from the resolve agent's `deferred` list: a decided finding with an entry there is filed as the person's deferral when the entry ships a mitigation or the finding has no planned task with files (`isDeferral` in `workflows/redline-loop.js`). A decision that fixes the finding in full has a task with files and should have no entry, but when the resolve agent also returns one with a mitigation, the workflow cannot tell it from a real "Mitigate" answer, which has the same shape. The fixed finding is then filed as a GitHub issue, with no question on autopilot, and its reply ends "Deferred to #N".
- **Why it is not fixed here:** Telling the two apart needs a new field in the resolve agent's output and in its agent file, a change to how the pull request's own spec has a chosen deferral reach the workflow; the review round that found it put the rule for when an entry is returned into the resolve prompt instead.
- **The fix proposed:** Add to the resolve agent's JSON the disposition each applied decision ends in (`fix`, `defer` or `accept`), ask for it in `agents/redline-resolve.md` and the resolve prompt, and have `isDeferral` read a decided finding's deferral from it rather than from the entry and the task's files; pin a fix beside a stray mitigated entry, a fix beside a stray empty entry, and a real "Mitigate" answer in `tests/loop-test.mjs`.
