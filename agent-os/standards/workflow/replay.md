# Replay

A relaunch replays every agent before the stopping point from cache, so every prompt before that point is byte-identical between the first launch and the relaunch.

- Nothing before a stopping point reads the clock: the launch timestamp is `args.launchedAt`, the spec folder name is derived from it, and `Date.now()` and `new Date()` do not appear in `workflows/redline-loop.js`
- Decisions, approved plans, selected findings and the answers to deferred drafts enter the workflow only after the prompt they answer (`args.decisions` after shaping, `args.approvedPlans` for the plan dial, `args.selected` for the review dial, `args.deferrals` at a stop check, at filing and in the text posted after it); a prompt before that point never mentions them; and a stop takes only a decision whose prompt comes after it, so a disposition override, which the round's first resolve applies, is taken only at a stop the round reaches before that resolve: a later stop of the round (a reshape after a bounced plan, a draft the resolve agent wrote) takes none and lists no declines (#94, R3-7, stated then as no plan approver having run; #95)
- An answer to something an agent wrote names the version it saw, and the workflow counts the version over the agent's text, never over the answer: a deferred draft's version rises when a reshape or the resolve agent changes the draft as written, a changed draft is raised again, and an answer to a later version covers the earlier ones, so the round's first stop still passes on a relaunch after its second (#95)
- A plan approval is keyed by the pass, not by a bare round number: `passOf(record).planKey` is a Redline round's number, or `h<n>` for a human review pass, since a human pass and its final nit pass can carry the same number (#38, R1-5)
- The skill relaunches with byte-identical `args` plus only what the stop asked for, and `resumeFromRunId` set to the run id it recorded at launch. A run the harness stopped is relaunched the same way with nothing added
- Every item a stop hands back is one the skill asks about and counts in `decisionsNeeded`: an override the resolve agent could not apply comes back as `overridesUnresolved` with its why, for the person to restate, since a stop with nothing to ask relaunches with the same args and replays the same refusal every time (#94, R4-8); a field a stop adds to the result is named in `relaunch.how` in the same commit, with what the relaunch passes for it, since a session reading the note would otherwise send the refused decision back unchanged (#94, R5-4); and the skill section that presents and records the new field lands in that commit too, since a stop the skill cannot answer relaunches into itself (#95, `drafts` and `draftsNeeded`); and `relaunch.how` gives each kind of answer the shape the skill records for it: its plan clause gave an ask the changed-disposition shape until #108, R3-2, which since #99 would let a guessed disposition decide a call
- A prompt names its inputs by path (`<specFolder>/redline/round-1-findings.json`), not by content, wherever the content can change between launches
- The GitHub agent never posts a round-N review when one already exists on the PR (`redline-gh.sh has-review`), so a fresh run after a lost session cannot double-post
- The first round number enters through `args.firstRound`: the skill reads the highest posted round with `redline-gh.sh last-round` before the launch and passes the next one, and the workflow never asks GitHub for it, since the answer changes as soon as the run posts (#33; #10, round numbering). A human review pass's number enters the same way, through `args.revise.n` from `redline-gh.sh last-human-review`, with the ingested comments as `args.revise.findings` (#36)
- The findings of the PR's earlier Redline rounds and their dispositions enter through `args.priorFindings`: the skill reads them with `redline-gh.sh prior-findings` after `last-round` and passes the list, and the workflow never reads the threads itself, since the run's own carried-forward replies change them (#35)
- Finish asks GitHub for state that changes as the run posts in two places, the read of the highest posted round (#81) and the thread sweep (which threads are open, and who spoke last in them, #39); both sit after every stopping point, so no prompt a relaunch replays depends on either. A stop at the end of the run (the deferred drafts held for it, #95) makes no agent call and is checked before Finish's first one; what it held is filed and replied to inside Finish, after the read of the highest posted round, so nothing is posted once that read refuses. What a round holds for it is recorded at round time from the setting alone, never from an answer, so no later round's prompt depends on one
- A per-repository list the prompts need (`askRules`, #49) enters through `args` at launch, read by the skill from `.claude/redline.json`, and is injected by appending to an existing interpolation, empty when there is none, so a repository without one keeps byte-identical prompts; the loop test proves it by comparing every prompt of a run with no key against one with `[]`
- A dial that turns a pass off leaves that pass's call and its block out of every prompt: `coverage off` reaches the workflow as `models.coverage` null, and the coverage call, the candidates block and its rules exist only when a pass ran. The loop test proves it per rule, each key phrase of the block being absent from a `coverage off` prompt (#79). Since #93 the off run follows the same model as the covered one, the reviewer finding and verifying alone, so its prompts are no longer those of the run before the pass existed
- `tests/loop-test.mjs` proves the rule: its relaunch scenarios assert that the prompts before the stopping point equal the first launch's, and a change that breaks that fails there before it reaches a PR
- A resume after an error changes exactly one prompt: `run()` appends a resume line to the agent label the error result's `resumeFrom` names (`args.resume`), so every prompt before it replays and that agent and all after rerun; a cached result the script rejected replays unchanged on a plain relaunch, which is why the line exists. A hand commit's paths join `approvedPaths` at that label, never at startup, so the cached snapshot prompt stays byte-identical (#10). A call the workflow makes because of a resumed step's answer (the verdict after a spilled check) carries that step's attempt number in its prompt, so the resume asks again and never replays what the earlier attempt was told. What a prompt before a resume point is built from changes only when a step completes: the snapshot's `round_sha` comes from `commitsAll`, which a round's commits join once its check has passed, so the snapshot of a resumed round is byte-identical and the commits a failed attempt made are still listed (#68); and a step whose stop is the workflow's own check of what that step returned is told so in its resume line, as the shaper is told to rewrite its folder: the resolve agent's rerun after a resolve-time stop was told only that the person had fixed the cause by hand, beside a `plan.md` its first attempt had already decided, until #108, R3-4; and that sentence is chosen by the stop, never by the agent alone: the resolve agent's was appended to every resume of a resolve, the autopilot stop raised from its own `unresolved` list included, whose rule keeps an unclear decision pending, until #108, R4-4; and the shaper's own sentence, rewrite the folder from scratch, is the wrong one beside entries the resolve agent decided: a reshape stopped by the workflow's check of the task it left a decided finding is told to correct the task and keep them, chosen by the stop, and a reshape resumed after any other stop keeps the shaper's sentence (#106); and a stop says what it is where it is raised, so that sentence is chosen by the field the stop set (`ownCheck`), never by the words of its error: the error result returns the field, the run marker carries it and the skill copies it into the resume entry, which is also how the skill tells the person that nothing needs fixing by hand, and an entry without it is an ordinary stop, with no fallback to the wording. Until #116 `resumeLine` read how the error opened (`the resolve agent `, `the reshape left `), so a check worded another way got the wrong sentence, and the skill told the person to fix the cause by hand after every resumable stop; and a stop whose resume line tells the rerun to correct what the error names names every failure of its check in one error, since each one it leaves out is one more relaunch: the hold after a reshape named only the fixes left with no task when the same reshape also gave an accepted finding one, until #114, R4-6; and a resume sentence that states an exception restates the rule it leaves standing: the correct-in-place sentence left out the from-scratch sentence's ban on touching `redline/`, until #114, R4-1
- On an interactive relaunch the harness relays the person's last typed message to every agent with precedence over its task; an `AskUserQuestion` pick is not relayed and a headless session relays nothing. The skill relaunches only from `relaunch` typed alone or a line holding only a Redline command, a namespaced form (`/redline:redline`, `/redline:redline-review`, `/redline:redline-revise`) or a short alias (`/redline`, `/redline-revise`) a repository's `.claude/commands/` provides, and `RUN_LINE` names both lines and every form (#60, #44; #63, R1-4)
- A relaunch runs the script the run launched with: by name while `workflows/redline-loop.js` is as launched, from the copy the harness persisted (as `scriptPath`) once it differs, which only the plugin's own repository can see (`redline-prefs.sh run drift`). Replay follows the prompt sequence: script path, script text outside the prompts, an agent's label and the agent file's body are not in the key. The `Workflow(<name>)` allow rule does not cover a `scriptPath` launch. Measured headless under `--plugin-dir` on 2.1.322 (#81)
- What changed since launch enters as `args.drift` on a relaunch and is read only at startup and at Finish; the loop test proves every prompt before Finish equals the run without it. Finish's own prompts replay on a resume past them, and the handoff comment names `drift.agents`, so an error or stopped resume passes the agent list its marker's args held (`redline-prefs.sh run drift` prints it so), only a hand-off or a `reviewed` relaunch reads it afresh, and the loop test proves every prompt through the comment replays on a record-commit resume with the held list (#91, R1-1). A run never finishes from a round below the highest posted: that stop is not resumable (#81)
- A new ask in a prompt sits in the block that only the calls it concerns carry, and nowhere else in that prompt, so a call it does not concern keeps a byte-identical prompt and still replays after an update. The schema requires the new key, and the workflow reads an absent one as empty wherever an unchanged prompt can replay an older result. The prompt states the whole ask, so the answer does not depend on the agent file the session loaded, and the agent file gains the ask and changes no other rule, so an older script reading a newer agent's output behaves as it did (#99, `decided` in the resolve prompt's calls block); a rule a later check enforces on the items of a block the new ask is not in, when stating it in that block would change a prompt the spec keeps byte-identical, is stated in the agent file alone, and the stop a script newer than the agent file can meet stays resumable, its resume line telling the rerun to correct what it wrote (#108, R4-9: an override's fix is a task of its own, its `finding` the override's id, in `agents/redline-resolve.md` and not in the overrides block); and a block that only says what an existing field means for the findings it names needs no new key: the reshape prompt's decided-findings block, in a round with a finding the person or autopilot decided and in no other (#106); and a sentence elsewhere in that prompt that states the field's general meaning is qualified under the block's own condition, so no sentence gives a finding the block names a second meaning (workflow/agents, line 50) and a prompt without the block stays byte-identical: the reshape's Return sentence still asked an ask for the paths of its recommended change beside the block until #114, R1-4; and the qualified clause names what it covers by the block's own test (an ask not named above as decided), never by a state word the same prompt uses for a narrower set: `an ask still pending` left out an ask the reshape newly raises, which the same Return sentence lists beside the pending ones, until #114, R2-4
