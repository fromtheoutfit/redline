# Tech Stack

## Runtime

- A Claude Code plugin: dynamic workflows (research preview; proven on 2.1.303, 2.1.304 and 2.1.306), subagents, a plugin `PreToolUse` hook, and skills. One workflow (`workflows/redline-loop.js`, run as `redline:redline-loop`), eight agents (`agents/redline-*.md`), four skills (`/redline:redline`, its two debug halves, and `/redline:setup`)
- Models per role from `.claude/redline.json` (Opus for the roles that read code, Haiku for the ones that move files and post); the revise model is chosen at launch and remembered per person

## Scripts

- Bash with `set -euo pipefail` for every script under `scripts/`; `jq` for JSON; `python3 -I` with the standard library for the guard's command parser
- `gh` for every GitHub call, through `scripts/redline-gh.sh`; authentication is `gh`'s
- Each repository's gate is its own `.claude/redline/checks.sh`, generated by `scripts/redline-setup.sh` from the repository's `.claude/redline/checks.json` and `scripts/checks-template.sh`; here it runs the nine steps in `.claude/commands/agent-os/shape-spec.md`, and carries the gate stamp that `scripts/redline-gate.sh` checks at launch and the template version line

## Tests

- Bash harnesses for the guard (`tests/guard-test.sh` over `tests/guard-cases.tsv`), the saved settings (`tests/prefs-test.sh`), the gate stamp (`tests/gate-test.sh` over `tests/gate-fixtures/`), the setup script (`tests/setup-test.sh` over `tests/setup-fixtures/`), the GitHub wrapper (`tests/gh-test.sh` over `tests/gh-fixtures/`, with a fake `gh`) and the background runner (`tests/background-test.sh`, with a stub `checks.sh`); Node, ESM, no dependencies, for the workflow (`tests/loop-test.mjs`)
- No framework, no package manager, no lockfile, no build step. CI is `.github/workflows/gate.yml`: on every push to a pull request and to `main`, on Ubuntu and macOS, the gate as the checker runs it (`.claude/redline/checks.sh --baseline`), then the stamp check, the template version check and a clean-tree check, with shellcheck required beside it; Claude Code is pinned there to 2.1.312 for `claude plugin validate`, and Node 22 comes from `.nvmrc`

## Planner and host

- Agent OS in the repository under review: `.claude/commands/agent-os/` (five commands) and `agent-os/` (product, standards, specs)
- GitHub, through `gh`; both are the only options in Phase 1 (see `roadmap.md`)

## Where the rest lives
